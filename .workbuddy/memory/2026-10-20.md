# 2026-10-20 项目分析与 UI 重构

## 项目概况
WPF (.NET 6, net6.0-windows) 扫码枪模拟器。MVVM 结构：CommunityToolkit.Mvvm 源生成器 +
Newtonsoft.Json 持久化到 `setting.json`。通信层 `IComm` → `AComm` 抽象基类 →
`CommSerialPort` / `CommTcpClient` / `CommTcpServer` 三个实现。

  （TextBox / ComboBox / CheckBox / 开关 / Button 四种变体 / TabControl /
  ListBox / ScrollBar / ToolTip 的完整 ControlTemplate）。

  右侧「属性 / 运行日志」页签 + 底部状态栏。属性面板按「基础设置 / 接口配置 /

  空→可见性、整数→可见性）与 `Models/LogEntry.cs`（带级别的日志条目）。

## 修复的既有缺陷
1. **切换接口类型丢失全部参数** —— `ScannerWrap.InterfaceType` 变更时直接 `new` 一个
   通信对象，IP/端口/内容等全部归零。新增 `AComm.CopySettingsTo()` 复制配置。
2. **启用开关无法恢复** —— `ScannerWrap.CheckScannerIsEnabled()` 轮询里调用
   `Scanner.Dispose()`，而 `Dispose()` 会置 `IsDisposed = true`，导致通信类内部
   `while (!IsDisposed)` 工作循环永久退出。改为不再调 Dispose（各通信类自身循环
   已在 `IsEnabled == false` 时释放端口/连接并可恢复）。
3. **配置文件内外层接口类型不一致** —— 历史 `setting.json` 中外层 `InterfaceType`
   与内层 `AComm.InterfaceType` 恒为 0（脏数据）。现在加载时自动同步，
   重新保存后脏数据被修正。
4. **底层对象替换时事件丢失** —— 新增 `ScannerWrap.ScannerReplaced` 事件，
   视图模型据此重新挂接消息/异常回调。
5. **线程安全隐患** —— 原 `Message` 字符串在通信线程上被 `+=` 追加。改为
   `ObservableCollection<LogEntry>`，追加时切回 UI 线程。
6. `BoolReverseConverter` 强转 bool，绑定值为 null 时抛异常，改为安全判空。

## 后续：全项目问题点审查（只读，未改业务代码）
产出 `分析报告-项目问题点.md`，共 23 条问题，分 P0/P1/P2。
P0（5 条）：串口 `Open()`、TCP `ConnectAsync()`、TCP 服务端 `Start()` 都在 try 块之外，
失败即杀死 `while(!IsDisposed)` 工作循环导致模拟器静默失效；`AComm.Dispose()` 不释放
底层资源（串口/Socket/TcpListener 端口）；`ScannerWrap.Dispose()` 从未被调用（泄漏线程）。

`_clients` 列表并发 Add/Clear 无锁；`CommTcpServer.DoWork` 有 `continue` 死代码；
`ParseAndSend` 语义与枚举描述矛盾；`setting.json` 用相对路径（依赖 CWD）；
`TypeNameHandling.Auto` 把程序集名写死进配置；日志无上限；`MessageBox` + `Dispatcher.Invoke` 阻塞通信线程。

## P0 修复（17:24 追加）
按审查报告修完 5 条 P0：
1. `CommSerialPort` 抽出 `TryOpenSerialPort()`，失败上报 + 退避 2s 重试，不再冲出工作循环；
2. `CommTcpClient` 抽出 `TryConnectAsync()`，同样自捕获重试；
3. `CommTcpServer` 抽出 `TryStartServer()`，**失败时必须复位 `_server`**（原来空 catch 导致永不重试）；
4. `AComm` 新增 `protected virtual ReleaseResources()` 钩子，三个子类重写释放串口/Socket/监听端口；`Dispose()` 改幂等；
5. `ScannerWrap.Dispose()` 改为在删除模拟器时调用；新增 `MainWindowViewModel.DisposeAll()` 在窗口关闭时释放全部。

顺带修的并发隐患：`_sp`/`_client`/`_server`/`_clients` 全部加锁；
打开流程与释放流程并发时检测 `IsDisposed` 立即丢弃刚申请的句柄；
`Post()` 由 `Dispatcher.Invoke` 改 `BeginInvoke`（模态窗口不再卡死通信线程），
并处理「无 UI 线程直接执行」「已在 UI 线程直接执行」两种分支；
删掉 `CommTcpServer.DoWork` 中被 `continue` 屏蔽的约 60 行死代码。

新增 `tools/UiRenderTest/P0ResilienceCheck.cs`：验证连接失败后持续重试且端点就绪后自动恢复、
Dispose 后监听端口真正释放、三种类型 Dispose 幂等。34 项测试全绿，应用实跑 10 秒无崩溃。

## 新增单元测试项目（17:38 追加）
`tests/模拟扫码枪.Tests`，xUnit 2.9.2 + net6.0-windows + UseWPF，已加入 `模拟扫码枪.sln`。
118 个用例全绿（快速 105 个仅 139ms，`Category=Slow` 的 13 个集成测试约 18s）。

踩坑（重要）：
1. **`dotnet new xunit -n 中文名` 会失败**（模板不支持中文名），必须手工写 csproj。
2. **xUnit 并行 + `Directory.SetCurrentDirectory` 互斥**：因 `setting.json` 用相对路径，
   测试类各自切目录会互相干扰，表现为「单跑通过、全跑失败」。
   解法：`TempDirTestBase` 给每个用例分配 GUID 临时目录 + `[Collection(DisableParallelization)]`。
3. **端口探测必须用 `IPAddress.Any`**：`CommTcpServer` 绑 0.0.0.0，
   用 `Loopback`(127.0.0.1) 探测不冲突 → 误判端口空闲，让「Dispose 后端口释放」的断言失效。
4. **MessageBox 会永久阻塞测试进程**：已把 `RemoveItem` 的确认逻辑抽成
   `protected virtual bool ConfirmRemove(string)`，生产行为不变，测试用 `AutoConfirmViewModel` 覆盖。
5. net6.0 不支持 C#11 原始字符串字面量（`"""..."""`），报 CS8936；测试里改用 `+` 拼接。
6. 静态字段与实例属性不能同名（CS0198），基类里锚点目录要用不同名字。

## 踩坑记录
- XAML 中 `ConverterParameter` 含逗号时必须加引号：`ConverterParameter='A,B'`。
- `Path` 的线帽属性是 `StrokeStartLineCap` / `StrokeEndLineCap`（不是 `StrokeStartLine`）。
- `ContentPresenter` 没有 `Foreground` 属性，禁用态要设 `TextElement.Foreground`；
  直接设 `TextElement.Foreground` 反而抛 UnsetValue 异常，改用 ComboBox 的 `Foreground`。
- CommunityToolkit 源生成的 `partial void OnXxxChanged(T? oldValue, T newValue)`
  第二个参数是不可空类型，签名写错会报 CS8826。
- `Path` 在 WPF 中只有 `StrokeStartLineCap`，`StrokeEndLineCap` 同理。

## 追加：ComboBox 显示空白修复（2026-10-21）

**根因**：WPF `ComboBox.SelectedItem` 绑定到不在 `ItemsSource` 中的值时，
绑定框架会把 `SelectedItem` 置 null；而 `Themes/Controls.xaml` 的 `AppComboBox` 模板用
`ContentPresenter Content="{TemplateBinding SelectionBoxItem}"` 渲染 → 显示空白。
**源值本身没丢，丢的是显示**（实测 SelectedItem=null、Text=''、回写后源值仍为原值）。

**修复三要素**（缺一不可）：
1. 候选列表合并当前值：`AComm.SerialPortNameValues` / `SerialPortBaudRateValues` /
   `SerialPortDataBitsValues` 都把当前值并入列表；
2. 枚举归一化：`AComm.NormalizeEnum<T>()` + 7 个枚举属性 setter 回退到首个合法值；
3. 写回防护：setter 拒绝 null / 越界值，防止 TwoWay 绑定把 null 反写回源。

**踩坑**：
- `AComm` 里 `ParityValues`/`StopBitsValues` 重复定义 → CS0102，编译前先 grep 排查。
- `MainWindow.xaml` 波特率/数据位 ComboBox 原本写死内联 `<sys:Int32>` 集合，必须改成
  `ItemsSource="{Binding Scanner.SerialPortBaudRateValues}"` 才生效。
- WPF 渲染工具里 `visual is FrameworkElement fe && fe.ActualWidth > 0` 这种写法
  在 net6.0 编译期报 CS0165（模式变量未赋值），改用 `as` + 独立方法。
- 诊断用的临时文件（ComboProbe.cs / DiagEntry.cs）用完要删，
  并从测试 csproj 移除 `GenerateProgramFile=false` + `StartupObject`，否则测试入口被劫持。

**验证**：编译 0 错误；单元测试 141 项全绿（原 118 + `ComboBoxBindingTests` 23 项）；
新增 `tools/UiRenderTest/ComboCheck.cs`（combo 模式）12 项断言全 PASS；
原 30 项功能回归全 PASS。
